# Shio (潮) — спецификация v1

Дата: 2026-11-12 · Статус: на проверке у владельца

## 1. Цель

Shio — личное приложение для **funding-арбитража** криптовалют. Оно работает 24/7 на сервере, а управляется
с телефона и компьютера через веб-приложение.

**Критерии успеха v1**
- Бот круглосуточно находит связки, открывает и ведёт позиции и закрывает их по правилам без участия человека
  (в режиме «Автомат») или по одному нажатию (в режиме «Полуавтомат»).
- Ни одна позиция не остаётся без защиты: нет «висящих» одиночных ног, ликвидации предотвращаются.
- Реальная доходность (по фактическим выплатам funding за вычетом комиссий) видна в приложении и совпадает с биржами.
- До реальных денег бот минимум 2 недели работает в виртуальном режиме, и его результат сходится с расчётами.

**Ограничения и ожидания**
- Стартовый капитал $500, владелец в Украине.
- Реалистичная доходность — 15–40% годовых (≈ $6–17 в месяц с $500), в хорошие периоды с агрессивным профилем больше.
  **Доход не гарантирован.** Рост дохода достигается увеличением капитала, а не риском.
- Один пользователь. Не продукт для продажи.

## 2. Объём

**Входит в v1**
- Две стратегии: «спот + шорт фьючерса» на одной бирже и «фьючерс против фьючерса» на двух биржах.
- Два профиля: «Спокойный» и «Агрессивный» (экстремальные ставки и новые листинги, не больше 30% капитала).
- Режимы «Виртуальный / Реальный» и «Полуавтомат / Автомат».
- Веб-приложение (PWA) для телефона и компьютера, Telegram-бот, развёртывание на VPS.
- Уведомления о новых пулах Launchpool / Launchpad / Jumpstart (только уведомления, без автоматического участия).

**Не входит в v1 (кандидаты в v2)**
- Межбиржевой арбитраж спота.
- Автоматический перевод денег между биржами (выводы).
- Несколько пользователей, сложные графики цен, другие стратегии.

## 3. Биржи

| Биржа | Наблюдение | Торговля | Примечание |
|---|---|---|---|
| Bybit | да | да | единый счёт, спот и фьючерсы |
| OKX | да | да | единый счёт |
| Hyperliquid | да | да | DEX, выплаты каждый час; торгует через API-кошелёк (agent), который не может выводить средства |
| Binance | да | по выбору | спот и фьючерсы — разные кошельки, нужен внутренний перевод |
| Bitget | да | по выбору | |
| Gate | да | нет | источник экстремальных ставок |
| WhiteBIT | да | нет | нельзя автоматически проверить отсутствие права вывода у ключа |
| MEXC | да | нет | только наблюдение: история заморозок выводов |

Все биржи подключаются через ccxt. Список «торговать / наблюдать» меняется в настройках.
Coinbase не используется: не отдаёт текущие ставки funding.

Доступность из Украины проверена по сторонним обзорам: все биржи работают, кроме оккупированных территорий.
Перед подключением каждой биржи владелец сверяется с её актуальными правилами.

## 4. Стратегии и расчёт

- **Спот + шорт** (одна биржа): покупка спота и шорт фьючерса на равный номинал. Работает при funding > 0.
- **Фьючерс / фьючерс** (две биржи): шорт там, где ставка выше, лонг там, где ниже. Ставки нормируются на час,
  потому что интервалы выплат разные (1, 4, 8 ч).
- **Доход** считается консервативно: по `min(текущая ставка, средняя за последние 21 выплату)`,
  минус 4 комиссии (вход и выход каждой ноги), на капитал, задействованный в связке.
- **Фильтры**: минимальный оборот фьючерса и спота, разница цен между ногами ≤ 2% (иначе это, скорее всего,
  разные токены), глубина стакана выдерживает сумму с проскальзыванием ≤ 0,1%.
- **Оценка истории**: «стабильно», «всплеск» (текущая ставка намного выше средней), «история против».
- Основа — уже готовый и протестированный модуль `scanner/calc.py`.

## 5. Режимы

| | Полуавтомат (по умолчанию) | Автомат |
|---|---|---|
| Вход | предложение в Telegram и в приложении, действует 15 минут, вход по кнопке | сам, если связка проходит правила |
| Защита позиций | бот сам | бот сам |
| Выход при развороте ставки | предлагает | сам |

**Виртуальный режим** проходит весь путь, но сделки симулируются по реальному стакану с реальными
комиссиями, а funding начисляется по фактическим ставкам в момент выплаты.
Переключение на «Реальный» требует подтверждения кодом 2FA.

## 6. Архитектура

Один сервер, три процесса в Docker Compose:

```
┌──────────────────────── engine (Python, asyncio) ────────────────────────┐
│ Collector ─► Finder ─► Decider ─► Executor ─► Guardian ─► Ledger          │
│     ▲                       │          │           │          │           │
│     └── ccxt (8 бирж)        └─► Notifier (Telegram)  Reconciler (старт)   │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ SQLite (WAL): одна база, один файл
┌────────────── api (FastAPI) ─────┴──────┐      ┌──────── caddy ────────┐
│ REST + WebSocket для приложения,        │◄────►│ HTTPS, автосертификат  │
│ раздача собранного веб-приложения       │      └────────────────────────┘
└─────────────────────────────────────────┘
```

| Модуль | Что делает |
|---|---|
| **Collector** | раз в минуту: ставки, интервалы, цены, объёмы; история ставок для кандидатов |
| **Finder** | связки, расчёт дохода, фильтры, проверка глубины стакана |
| **Decider** | правила профилей и режима; создаёт предложение или команду на вход |
| **Executor** | вход и выход двумя ногами (раздел 7) |
| **Guardian** | каждые 30 секунд: маржа, перекос ног, разворот ставки |
| **Ledger** | фактические выплаты funding и комиссии из истории бирж, P&L |
| **Reconciler** | при старте и раз в 10 минут сверяет базу с реальными позициями на биржах |
| **Notifier** | Telegram: уведомления и кнопки подтверждения |

API и двигатель общаются **только через базу**: команды из приложения пишутся в таблицу `commands`, двигатель
их забирает. Если API упадёт, двигатель продолжит работать и защищать позиции.

**Основные таблицы**: `settings`, `exchanges` (зашифрованные ключи), `opportunities`, `proposals`, `positions`,
`legs`, `orders`, `funding_payments`, `fees`, `commands`, `audit_log`, `heartbeat`.

**Стек**: Python 3.11+, ccxt (async), FastAPI, SQLite (стандартный sqlite3, режим WAL), aiogram (Telegram), pytest.
Интерфейс: React + Vite + TypeScript, PWA.

## 7. Исполнение и риск

**Вход**
1. Проверить свободные балансы и при необходимости сделать внутренний перевод «спот ↔ фьючерсы» на той же бирже.
2. Подогнать размер под шаг лота обеих ног, чтобы номиналы совпадали.
3. Выставить плечо и режим маржи (изолированная) на фьючерсной ноге.
4. Открыть сначала менее ликвидную ногу (IOC-лимит с допуском проскальзывания), затем вторую.
5. Если вторая нога не открылась за 3 попытки, немедленно закрыть первую и сообщить в Telegram.
6. Частичное исполнение: выровнять вторую ногу по фактически исполненному объёму.

**Выход** — в обратном порядке, с той же защитой от одиночной ноги.

**Guardian**
- Запас до ликвидации ≤ 40% — предупреждение; ≤ 20% — довнести маржу из свободного баланса той же биржи,
  если не хватает — закрыть обе ноги.
- Перекос номиналов ног > 1% — выровнять.
- Ставка развернулась (ожидаемый доход за следующие 24 ч < 0) — закрыть (Автомат) или предложить (Полуавтомат).

**Лимиты по умолчанию** (меняются в настройках)

| Параметр | Значение |
|---|---|
| Плечо | до 3x |
| На одну связку | до 50% капитала |
| Связок одновременно | 3 |
| Агрессивный профиль | до 30% капитала |
| Мин. доходность для Автомата | 20% годовых |
| Дневной убыток | 5% → пауза бота и уведомление |
| «Стоп всё» | закрыть все позиции, с подтверждением |

## 8. Безопасность

- Вход в приложение: пароль (argon2) + TOTP-код. 5 неверных попыток — блокировка на 15 минут и уведомление в Telegram.
  Вход с нового устройства — уведомление.
- API-ключи: AES-256-GCM, ключ шифрования в файле окружения на сервере, не в базе. В браузер ключ не возвращается
  (видно только `abcd••••wxyz`).
- При добавлении ключа проверяются права: **ключ с правом вывода не сохраняется** (Binance, Bybit, OKX, Bitget).
  Где проверить нельзя, показывается предупреждение. Приложение показывает IP сервера для привязки ключей.
- Hyperliquid: только API-кошелёк (agent), который не может выводить средства.
- Telegram-бот отвечает только на chat_id владельца. Закрытие и «Стоп всё» — с подтверждением.
- Сервер: только HTTPS; снаружи открыты порты 443 и 22; SSH только по ключу; автообновления безопасности.
- Журнал всех действий (`audit_log`) виден в приложении.

## 9. Интерфейс

**Стиль**: «живой» тёмный интерфейс, палитра **«Королевский синий»** (вариант 6). Эталон — `docs/design/shio-live.html`
и `docs/design/main-screen.png`.

|---|---|
| фон | `#05061A` |
| текст / приглушённый | `#F5F7FF` / `#9B9FC4` |

| основной синий | `#4D5BFF` |

**Элементы стиля**: переливающийся фон-сияние, жидкая сфера с волнами (наполняется к следующей выплате),
баланс «набегает» при открытии, графики прорисовываются, карточки из матового стекла, плавающее меню-капсула.
Шрифт Onest. Учитывается системная настройка «Уменьшить движение».

**Экраны**: Главная · Связки · Открыть связку · Позиции · История (сделки, выплаты, экспорт CSV) · Биржи ·
Настройки · Состояние (связь с биржами, последнее обновление, сервер) · Журнал действий · Вход (пароль + 2FA).
На компьютере меню вверху, на телефоне снизу. Устанавливается на главный экран iPhone и Android как PWA.

## 10. Telegram

- Предложение связки с кнопками «Открыть» / «Пропустить».
- Позиция открыта или закрыта, выплата получена (по желанию — сводка раз в день).
- Предупреждения: маржа, разворот ставки, ошибка биржи, пауза из-за дневного лимита.
- Новые Launchpool / Launchpad / Jumpstart.
- Безопасность: вход, неверный пароль, новое устройство.
- Ежедневная зашифрованная резервная копия базы файлом.
- Команды: `/status`, `/positions`, `/pause`, `/resume`, `/stop` (с подтверждением).

## 11. Работа 24/7

- VPS с 2 ГБ памяти, около $5–7 в месяц. Страна выбирается так, чтобы её не было в списках ограничений
  ни одной из торговых бирж (не Сингапур и не США).
- Docker Compose: `engine`, `api`, `caddy`; `restart: always`; запуск после перезагрузки сервера.
- Сторож: двигатель раз в минуту отправляет сигнал во внешний сервис (healthchecks.io). Если сигнала нет 3 минуты,
  приходит уведомление в Telegram — даже если сервер полностью упал.
- Резервные копии: ежедневно в Telegram; восстановление одной командой.
- Обновление: `git pull` + перезапуск одной командой (скрипт `deploy.sh`). При старте Reconciler сверяет позиции.
- Код хранится в приватном GitHub-репозитории владельца.

## 12. Ошибки и сбои

| Ситуация | Поведение |
|---|---|
| Биржа не отвечает | повтор с паузами; новые входы на этой бирже запрещены, открытые позиции продолжают охраняться через доступные данные; уведомление |
| Ордер отклонён | до 3 повторов; при неудаче второй ноги — закрыть первую |
| Сбой посреди операции | при старте Reconciler сверяет базу с биржами и сообщает о расхождениях; осиротевшая нога закрывается |
| Расхождение баланса | пауза входов, уведомление |
| Дневной лимит убытка | пауза бота до ручного возобновления |
| Падение API | двигатель работает независимо |

## 13. Тестирование

- **Модульные тесты**: расчёты, фильтры, правила профилей, лимиты (pytest, без сети).
- **Тесты исполнения** на поддельной бирже: частичные исполнения, отказ второй ноги, обрыв связи, перезапуск посреди операции.
- **Тестовые сети бирж** (Bybit testnet, OKX demo, Hyperliquid testnet): реальные ордера без реальных денег.
- **Виртуальный режим минимум 2 недели** на реальных данных: расчётный доход сравнивается с фактическими ставками.
- **Реальные деньги**: сначала $50–100 под присмотром, потом весь капитал, потом Автомат.

## 14. Этапы

1. **Двигатель + виртуальный режим**: Collector, Finder, Decider, Executor (виртуальный), Guardian, Ledger, база.
2. **Telegram-бот**: уведомления, предложения с кнопками, команды.
3. **Веб-приложение**: API, вход с 2FA, все экраны в утверждённом стиле.
4. **Сервер 24/7**: Docker, Caddy, сторож, резервные копии, инструкция по установке.
5. **Реальная торговля**: Executor на тестовых сетях, затем малая сумма, проверка ключей.
6. **Автомат и агрессивный профиль**: после подтверждения работы полуавтомата.
