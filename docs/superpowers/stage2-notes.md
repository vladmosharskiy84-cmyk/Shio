# Shio — этап 2 (Telegram): решения и отложенное

## Решения (rulings)
- R1. `chat_id_from_update` + тест разбора для `telegram-id`.
- R2. Runner хранит `stats["marks"]`, чтобы `/positions` показывал запас до ликвидации (маленькая запись в kv на каждый тик защиты).
- R3. Бэкап не доставлен в Telegram → файл сохраняется локально, повтор доставки каждые 20 мин до конца суток UTC; день отмечается только после подтверждённой доставки.
- R4. Доставка в Telegram отвязана от Runner: ограниченная очередь + фоновый воркер, таймауты 10 с (документ 120 с), пауза 60 с после сбоя, `retry_after` ≤ 30 с. Runner ждёт Telegram максимум ~2 с (только `send_document`).
- R5. Бот слушается только личный чат владельца (`chat.id == from_user.id == chat_id`); группы не поддерживаются.
- R6. Временные ошибки (сеть, таймаут, 5xx, flood, HTML-ответ шлюза) возвращают сообщение в голову очереди; постоянные (4xx) — выброс с логом и аудитом. Предел возраста: info/предложения 1 ч, warn/alert 12 ч. Переполнение: сначала info, потом предложения, потом остальное. Просроченные предложения не отправляются.

## Отложено (не блокирует)
- Отозванный токен / заблокированный бот: по строке аудита на каждое сообщение — можно ограничить раз в час.
- Очередь может превысить предел на 1 элемент при возврате в голову.
- `tg_msg:proposal:<id>` пишется, но не используется (кнопки не убираются при истечении); kv `tg_done:*`, `tg_foreign:*` не чистится.
- Источники Launchpool (Bybit `new_crypto`, OKX `new-listings`) не проверены вживую — проверить при первом запуске; ключевое слово «megadrop» — термин Binance.
- Бэкап > 50 МБ не уйдёт в Telegram (лимит ботов); локальные бэкапы `data/backups/` без ротации.
- Восстановленная БД выполнит свои `new`-команды при следующем запуске.
- Сводка дня отмечается выполненной даже при неудачной доставке текста (она есть в логе и аудите).
- Из ревью задач: частичный сбой разбиения, `_last_sent` не чистится, сессия Bot discovery, `.gitkeep`, дубли имён источников.
- Вне этапа: уведомления о входе/новом устройстве (этап 3, веб), watchdog и корректное завершение по SIGTERM (этап 4), реальные деньги (этап 5).
