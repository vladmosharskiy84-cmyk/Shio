# Shio — этап 4 (сервер 24/7): решения и отложенное

## Решения
- S1. Веб-приложение (этап 3) отложено до подтверждения стратегии; в Compose пока только `engine`. При возврате к этапу 3: добавить `api` и `caddy` (§6, §14 п.4), порт 443; помнить, что Docker обходит ufw для опубликованных портов.
- S2. Настройки владельца — в `config.local.yaml` (не в git), рекурсивно поверх `config.yaml`; пустой заголовок секции ничего не меняет. Так `git pull` в `deploy.sh` не конфликтует.
- S3. Отдельной проверки задачи 4 не было: её проверило финальное ревью всей ветки.
- S4. Сторож зависания: нет ни одной завершённой задачи 10 минут → `os._exit(1)`, Docker (`restart: always`) поднимает движок. После некорректной остановки (остался сигнал «жив») при старте приходит предупреждение в Telegram. Восстановление из копии снимает скопированный сигнал «жив».

## Проверено вживую (Docker в песочнице)
Сборка образа; `./deploy.sh` → healthy за ~10 с и статус; нет `.env` → понятная ошибка; `./deploy.sh doctor`; `./deploy.sh restore` (данные вернулись, прежняя база сохранена); остановка по SIGTERM ~1 с.
Не проверено отсюда (сеть закрыта): доступ к биржам, Telegram, источники Launchpool, healthchecks.io — первая проверка будет `./deploy.sh doctor` на сервере.

## Отложено
- При срабатывании сторожа зависания нет корректной остановки (как при kill); позиции сверяет Reconciler при старте.
- Мелочи из ревью: группа на data/ не учитывается; `pytest` в образе; нет `init: true`; restore печатает путь внутри контейнера; нет теста на путь с пробелами в `deploy.sh restore`.
- Отдельный сторож «замёрзшего» цикла asyncio (задача, кормящая раз в 10 с) — при необходимости.
