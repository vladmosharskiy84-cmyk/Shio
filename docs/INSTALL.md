# Установка Shio на сервер — пошагово

Эта инструкция для человека без опыта администрирования. Делайте шаги по порядку, ничего не
пропуская. Каждая команда стоит в отдельной серой рамке: скопируйте её целиком, вставьте в окно
терминала и нажмите Enter. Под командой написано, что она делает и какой ответ означает «всё в
порядке».

Пара правил:

- Текст в угловых скобках, например `<IP-сервера>`, — это место, куда надо подставить своё
  значение. Скобки `<` и `>` тоже убираются: `ssh root@<IP-сервера>` → `ssh root@203.0.113.10`.
- Вставить текст в окно терминала: правая кнопка мыши (Windows) или Cmd+V (Mac).
- Когда терминал просит пароль, символы при вводе не отображаются (даже звёздочками). Это нормально:
  вводите или вставляйте и нажимайте Enter.
- У каждого шага помечено, **где** выполнять команду: на **вашем компьютере** или на **сервере**.
- Если что-то пошло не так, смотрите раздел [«Что делать, если…»](#что-делать-если) в конце.

Займёт это примерно 1–2 часа.

## 0. Перед началом

**Менеджер паролей.** Заведите его заранее (например, Bitwarden, 1Password или KeePass): по ходу
инструкции туда нужно сохранить:

- **ключ резервных копий** `SHIO_BACKUP_KEY` (шаг 6) — без него резервные копии не расшифровать;
- **пароль пользователя shio** на сервере (шаг 2.3) — его спрашивает каждая команда с `sudo`;
- **токен GitHub** (шаг 4.1) и **дату, когда он истекает** — поставьте себе напоминание за неделю;
- токен Telegram-бота (шаг 5.1) и копию SSH-ключа (шаг 2.1).

**SSH-ключ — до заказа сервера.** Сначала сделайте шаг 2.1, а при заказе вставьте публичный ключ
в поле «SSH key»: так в сервер с первой минуты можно войти по ключу.

**Проверка личности.** Hetzner может попросить подтвердить личность (фото документа) — это
обычная процедура. Если не хотите или вам отказали, подойдут DigitalOcean, Vultr или Netcup с
расположением **Франкфурт** (Frankfurt) или **Амстердам** (Amsterdam) — те же требования: Ubuntu
24.04, память от 2 ГБ.

**Биржи.** Пускают ли биржи сервер из выбранной страны, точно покажет самопроверка `doctor`
(шаг 8). Её стоит сделать в тот же день, что и заказ: если биржа заблокирована, сервер проще
сразу пересоздать в другой стране.

## 1. Что купить

Нужен виртуальный сервер (VPS):

- **Память (RAM): 2 ГБ** или больше, 1–2 процессора, диск от 20 ГБ.
- **Система: Ubuntu 24.04 LTS.**
- **Цена:** примерно $5–7 в месяц.
- **Страна: Германия, Финляндия или Нидерланды.** Например, Hetzner Cloud: самый дешёвый тариф
  с памятью от 2 ГБ (на момент написания — CX22, примерно €4–5 в месяц), расположение
  Nuremberg / Falkenstein (Германия) или Helsinki (Финляндия). Если Hetzner не подходит —
  DigitalOcean, Vultr или Netcup во Франкфурте или Амстердаме (см. «Перед началом»).

**Нельзя: США и Сингапур.** Биржи не обслуживают эти страны и блокируют запросы с серверов там.
У Hetzner тоже есть площадки в США (Ashburn, Hillsboro) и Сингапуре — их не выбирайте. Вообще
избегайте любых стран из списков ограничений бирж Bybit, OKX и Hyperliquid. Доступны ли биржи
именно с вашего сервера, точно покажет самопроверка `doctor` (шаг 8): если там будет ❌ с
пометкой о блокировке по стране, сервер придётся пересоздать в другой стране.

При заказе провайдер предложит добавить SSH-ключ. Сначала сделайте шаг 2.1 (создать ключ), потом
вставьте свой **публичный** ключ в это поле. После заказа запишите **IP-адрес сервера** (четыре
числа через точку) — он понадобится дальше.

## 2. Безопасный вход на сервер

### 2.1. Создать SSH-ключ (на вашем компьютере)

SSH-ключ — это пара файлов: секретный остаётся только на вашем компьютере, публичный кладётся на
сервер. Вход по ключу надёжнее пароля.

Откройте терминал: на Windows — **PowerShell** (Пуск → набрать «PowerShell»), на Mac — **Terminal**.

```bash
ssh-keygen -t ed25519
```

Создаёт ключ. На все вопросы просто нажимайте Enter (можно задать пароль к ключу — тогда его
придётся вводить при каждом входе). OK — в конце появится рисунок из символов в рамке.
Если спросит `Overwrite (y/n)?` — у вас уже есть ключ: ответьте `n` и используйте его.

```bash
cat ~/.ssh/id_ed25519.pub
```

Показывает **публичный** ключ — одну строку, начинается с `ssh-ed25519`. Её и вставляйте в поле
«SSH key» при заказе сервера. Файл `id_ed25519` (без `.pub`) никому не отправляйте.

### 2.2. Первый вход (на вашем компьютере)

```bash
ssh root@<IP-сервера>
```

Подключается к серверу как администратор root. При первом входе спросит
`Are you sure you want to continue connecting (yes/no)?` — напечатайте `yes` и Enter.
OK — строка приглашения сменится на что-то вроде `root@имя-сервера:~#`.
Все команды до шага 2.4 выполняются **на сервере** в этом окне.

### 2.3. Обновить систему и создать своего пользователя (на сервере, под root)

```bash
apt update
```

Скачивает список обновлений. OK — в конце `Reading package lists... Done` и нет строк с `E:`.

```bash
apt -y upgrade
```

Ставит обновления (несколько минут). Если появится розовое окно с вопросом о настройках — нажмите
Enter (оставить как есть). OK — команда закончилась без строк `E:`.

```bash
adduser shio
```

Создаёт пользователя `shio`, под которым будет работать бот. Попросит дважды придумать пароль —
**запишите его в менеджер паролей**, он нужен для команд `sudo`. Остальные вопросы (Full Name и
т. д.) пропускайте Enter, в конце ответьте `Y`.

```bash
usermod -aG sudo shio
```

Разрешает пользователю `shio` выполнять команды администратора через `sudo`. OK — ничего не печатает.

```bash
rsync --archive --chown=shio:shio ~/.ssh /home/shio
```

Копирует ваш SSH-ключ пользователю `shio`, чтобы он тоже входил по ключу. OK — ничего не печатает.

```bash
id -u shio
```

Показывает номер пользователя shio. OK — `1000` (так у пользователя бота внутри контейнера).
Если другое число — ничего страшного: при запуске `deploy.sh` напечатает команду
`sudo chown -R 1000:1000 …/data`, её нужно будет выполнить (см. «Что делать, если…»).

### 2.4. Проверить вход под shio (на вашем компьютере, в НОВОМ окне)

Не закрывайте окно с root! Откройте второе окно PowerShell/Terminal:

```bash
ssh shio@<IP-сервера>
```

OK — вошли без пароля, приглашение `shio@имя-сервера:~$`.

- Если спрашивает `Enter passphrase for key …` — это пароль к самому ключу, если вы задали его в
  2.1. Всё в порядке: введите его.
- Если спрашивает `shio@<IP-сервера>'s password:` — ключ не скопировался. **НЕ делайте шаг 2.5**:
  после него вход по паролю закроется, и вы потеряете доступ. Нажмите Ctrl+C, вернитесь в окно
  root, повторите команду `rsync` из 2.3 и снова попробуйте войти.
- Если не получилось по другой причине — тоже не переходите к 2.5, сначала разберитесь (вернитесь
  в окно root и повторите 2.3).

Дальше **всё делаем под пользователем shio** в этом новом окне. Окно root можно закрыть после 2.5.

### 2.5. Запретить вход по паролю (на сервере, под shio)

```bash
printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin no\n' | sudo tee /etc/ssh/sshd_config.d/00-shio.conf
```

Запрещает вход по паролю и вход под root (останется только вход по ключу под shio).
Спросит пароль пользователя shio (из шага 2.3). OK — напечатает те же три строки.

```bash
sudo systemctl restart ssh
```

Применяет настройку. OK — ничего не печатает.

```bash
sudo sshd -T | grep -iE '^(passwordauthentication|permitrootlogin)'
```

Проверка. OK — две строки: `permitrootlogin no` и `passwordauthentication no`.

После этого ещё раз откройте новое окно и убедитесь, что `ssh shio@<IP-сервера>` по-прежнему
пускает.

**Если новое окно не пускает** (`Permission denied`) — не закрывайте окно, где вы уже вошли под
shio. Выполните в нём:

```bash
sudo rm /etc/ssh/sshd_config.d/00-shio.conf
```

```bash
sudo systemctl restart ssh
```

Вход по паролю снова разрешён. Разберитесь со входом по ключу (шаг 2.4) и только потом повторите
2.5. Если все окна уже закрыты — откройте «консоль» в панели провайдера (у Hetzner: сервер →
**Console**), войдите там как `shio` с паролем из 2.3 и выполните эти же две команды.

Если ваш компьютер сломается, войти на сервер можно будет только через «консоль» в
панели провайдера, поэтому храните копию файлов `~/.ssh/id_ed25519` и `id_ed25519.pub` в надёжном
месте (например, в менеджере паролей).

### 2.6. Брандмауэр (на сервере)

```bash
sudo ufw allow OpenSSH
```

Разрешает входящие подключения SSH. OK — `Rules updated`.

```bash
sudo ufw enable
```

Включает брандмауэр: все остальные входящие подключения закрыты (боту они сейчас не нужны; веб-
приложение появится позже). Спросит `Proceed with operation (y|n)?` — ответьте `y`.
OK — `Firewall is active and enabled on system startup`.

```bash
sudo ufw status
```

OK — `Status: active` и строки `OpenSSH ALLOW Anywhere`.

### 2.7. Автоматические обновления безопасности (на сервере)

```bash
sudo apt install -y unattended-upgrades
```

Ставит автоматическую установку обновлений безопасности (в Ubuntu 24.04 обычно уже стоит).
OK — `unattended-upgrades is already the newest version` или установка без `E:`.

```bash
sudo dpkg-reconfigure -plow unattended-upgrades
```

Включает их. В окне с вопросом выберите `<Yes>` и Enter.

```bash
systemctl is-enabled unattended-upgrades
```

OK — `enabled`.

### 2.8. Часы сервера (на сервере)

Биржи не принимают запросы от сервера с неверными часами.

```bash
sudo timedatectl set-ntp true
```

Включает автоматическую синхронизацию времени. OK — ничего не печатает.

```bash
timedatectl
```

OK — строки `System clock synchronized: yes` и `NTP service: active`. Часовой пояс сервера (UTC)
менять не нужно: бот всё считает в UTC.

## 3. Установка Docker (на сервере)

Docker запускает бота в изолированном «контейнере» и сам перезапускает его после сбоя или
перезагрузки сервера.

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
```

Скачивает официальный установочный скрипт Docker. OK — ничего не печатает.

```bash
sudo sh get-docker.sh
```

Устанавливает Docker и Docker Compose (1–3 минуты). OK — в конце нет слова `ERROR`, есть строки
про версии `Client` и `Server`.

```bash
sudo usermod -aG docker shio
```

Разрешает пользователю shio управлять Docker без `sudo`. OK — ничего не печатает.

```bash
exit
```

Выходит с сервера: новое право действует только после повторного входа. Войдите снова:

```bash
ssh shio@<IP-сервера>
```

```bash
docker ps
```

Проверяет, что shio может управлять Docker. OK — одна строка заголовка
`CONTAINER ID   IMAGE   COMMAND …` (список контейнеров пока пуст). Если пишет `permission denied` —
вы не перезашли на сервер.

```bash
docker compose version
```

OK — `Docker Compose version v2...`.

```bash
systemctl is-enabled docker
```

OK — `enabled`: Docker (а с ним и бот) запустится сам после перезагрузки сервера.

## 4. Скачать проект (на сервере)

Репозиторий https://github.com/vladmosharskiy84-cmyk/Shio приватный, поэтому серверу нужен
пропуск только **на чтение** и только **к этому репозиторию**.

### 4.1. Создать токен на GitHub (в браузере)

1. GitHub → ваш аватар справа вверху → **Settings** → внизу слева **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. **Token name:** `shio-server`. **Expiration:** например, 1 год (запишите дату — потом токен
   придётся заменить).
3. **Repository access:** **Only select repositories** → выберите **Shio**.
4. **Permissions** → **Repository permissions** → **Contents** → **Read-only**. Больше ничего не
   включайте (Metadata: Read-only GitHub добавит сам).
5. **Generate token** и скопируйте токен (начинается с `github_pat_`). Он показывается один раз —
   сохраните в менеджер паролей.

**Никогда не вписывайте токен в файлы проекта** (`.env`, `config.local.yaml`, README и т. п.) и
не отправляйте его в чаты. Он хранится только на сервере в служебном файле `~/.git-credentials`.

### 4.2. Скачать проект

```bash
sudo apt install -y git
```

Ставит git — программу для скачивания проекта. OK — `git is already the newest version` или
установка без `E:`.

```bash
git config --global credential.helper store
```

Разрешает git запомнить токен на этом сервере, чтобы обновления (`./deploy.sh`) не спрашивали его
каждый раз. OK — ничего не печатает.

```bash
git clone https://github.com/vladmosharskiy84-cmyk/Shio.git shio
```

Скачивает проект в папку `shio`. Спросит:
`Username` — ваш логин GitHub (`vladmosharskiy84-cmyk`), `Password` — **вставьте токен** (не пароль
от GitHub!). OK — `Receiving objects: 100%` и `done`.

```bash
cd ~/shio
```

Переходит в папку проекта. **Все следующие команды выполняются в ней**: после каждого нового входа
на сервер сначала выполняйте `cd ~/shio`.

```bash
ls
```

Показывает файлы проекта. OK — среди них есть `deploy.sh`, `docker-compose.yml` и `config.yaml`.
Файлов `.env.example` и `.gitignore` в списке нет — имена с точкой в начале скрыты, это нормально.

> **Вариант без токена — deploy key.** Вместо 4.1–4.2 можно на сервере выполнить
> `ssh-keygen -t ed25519` (все вопросы — Enter), показать ключ `cat ~/.ssh/id_ed25519.pub`, добавить
> его на GitHub: репозиторий Shio → **Settings** → **Deploy keys** → **Add deploy key**, галочку
> **Allow write access НЕ ставить**. Затем скачать проект командой
> `git clone git@github.com:vladmosharskiy84-cmyk/Shio.git shio` (на вопрос `yes/no` ответить `yes`).
> Такой ключ не истекает. Выберите один из двух вариантов.

### 4.3. Создать файлы настроек

```bash
cp .env.example .env
```

Создаёт файл `.env` для секретов (токены и ключи). Он не попадает в git. OK — ничего не печатает.

```bash
chmod 600 .env
```

Делает `.env` читаемым только для вас. OK — ничего не печатает.

```bash
cp config.local.yaml.example config.local.yaml
```

Создаёт файл **ваших** настроек `config.local.yaml`. Он не попадает в git, обновления его не
трогают, а его значения заменяют одноимённые из общего `config.yaml`. **Свои изменения вносите
только сюда, `config.yaml` не редактируйте** — иначе обновление (`./deploy.sh`) остановится с
ошибкой «git pull не удался».

```bash
mkdir -p data/backups
```

Создаёт папку для базы и резервных копий (если её создаст Docker, у неё будет неправильный
владелец). OK — ничего не печатает.

Как редактировать файлы: команда `nano <файл>` открывает простой редактор. Стрелками переходите к
нужному месту, печатаете. **Сохранить:** Ctrl+O, затем Enter. **Выйти:** Ctrl+X.

## 5. Telegram

Через Telegram бот присылает предложения сделок, тревоги, ежедневную сводку и принимает команды.

### 5.1. Создать бота (в Telegram)

1. Найдите **@BotFather** (с синей галочкой), нажмите Start, отправьте `/newbot`.
2. Придумайте имя и username бота (username должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** вида `1234567890:AAH...`. Сохраните его в менеджер паролей.

### 5.2. Вписать токен (на сервере)

```bash
nano .env
```

В строке `SHIO_TELEGRAM_TOKEN=` допишите токен сразу после `=`, без пробелов и кавычек:
`SHIO_TELEGRAM_TOKEN=1234567890:AAH...`. Сохраните (Ctrl+O, Enter) и выйдите (Ctrl+X).

### 5.3. Узнать свой chat_id (на сервере)

```bash
docker compose run --rm engine python -m engine telegram-id
```

Первый раз Docker сначала соберёт образ бота — это 2–5 минут, на экране бегут строки сборки.
Потом команда напишет «Напишите любое сообщение вашему боту в Telegram… Жду до 2 минут».
Откройте в Telegram **своего** бота (по username из 5.1), нажмите Start или напишите «привет».
OK — `Ваш chat_id: 123456789 (от: Имя, @username)`. Проверьте, что имя — ваше, и запишите число.
Бот в Telegram при этом ничего не отвечает — так и должно быть.

Если написано «Не задана переменная окружения SHIO_TELEGRAM_TOKEN» — токен не сохранился в `.env`
(повторите 5.2). «За 2 минуты никто не написал боту» — повторите команду и напишите боту быстрее.

### 5.4. Включить Telegram в настройках (на сервере)

```bash
nano config.local.yaml
```

Найдите строки:

```yaml
telegram:
  enabled: false       # true — включить уведомления и управление через Telegram
  # chat_id: 123456789   # ваш chat_id (123456789 — только пример)
```

Сделайте три правки:
1. `enabled: false` → `enabled: true`.
2. В строке с `chat_id` удалите `# ` в начале, чтобы она начиналась с двух пробелов, ровно под
   словом `enabled`.
3. **Замените `123456789` на свой chat_id из 5.3.** `123456789` — только пример; если его оставить,
   самопроверка (шаг 8) покажет ❌.

Должно получиться (с вашим числом):

```yaml
telegram:
  enabled: true        # true — включить уведомления и управление через Telegram
  chat_id: 987654321   # ваш chat_id (123456789 — только пример)
```

Сохраните и выйдите.

## 6. Ключ резервных копий (на сервере)

Раз в сутки (в 03:00 UTC) бот шифрует копию своей базы и присылает её вам в Telegram файлом
`shio-ГГГГ-ММ-ДД.db.enc`. Расшифровать её можно только этим ключом.

```bash
openssl rand -base64 32
```

Генерирует случайный ключ. OK — одна строка из 44 символов, заканчивается на `=`.

**Сразу сохраните этот ключ вне сервера — в менеджер паролей.** Без ключа резервные копии
бесполезны: если сервер пропадёт, базу не восстановить. Ключ не пересылайте в чаты и никому не
показывайте.

```bash
nano .env
```

## 7. Сторож healthchecks.io (в браузере и на сервере)

Если бот остановится или сервер выключится, сам бот уже ничего не сможет сообщить. Поэтому бот
каждые 60 секунд отправляет сигнал «жив» на внешний сайт healthchecks.io, а тот пишет вам в

2. Нажмите **Add Check**. Назовите проверку `Shio`.
3. В блоке расписания (**Schedule** / **Change Schedule**, вкладка **Simple**) поставьте
   **Period = 1 minute** и **Grace Time = 3 minutes**, сохраните.
4. Откройте вкладку **Integrations** → **Telegram** → **Add Integration** и следуйте подсказкам на
   странице: откроется их бот в Telegram, нажмите Start, он пришлёт ссылку — откройте её и
   подтвердите. Это **их** бот, не ваш. На странице проверки `Shio` убедитесь, что Telegram
   включён в списке оповещений (Notification Methods). Там же можно нажать «тест» и получить
   пробное сообщение.
5. На странице проверки скопируйте **ping URL** вида `https://hc-ping.com/xxxxxxxx-xxxx-...`.

```bash
nano .env
```

Впишите адрес в строку `SHIO_HEALTHCHECK_URL=` (сразу после `=`, без пробелов и кавычек).
Сохраните и выйдите.

Проверка заполнения `.env`:

```bash
grep -cE '^SHIO_[A-Z_]+=.+' .env
```

OK — `3`: заполнены все три строки (токен, ключ, адрес сторожа). Меньше — какая-то пустая,

## 10. Обычная жизнь с ботом

### Каждый день

- Читайте сообщения бота в Telegram: предложения сделок с кнопками «Открыть» / «Пропустить»,
  тревоги, **ежедневную сводку** (в 18:00 UTC — по Киеву это 20:00 зимой и 21:00 летом): капитал,
  P&L за день, funding за день, открытые связки.
- Раз в день отправьте `/status`: строка `Бот: работает` и свежий `последний сигнал`.
  `/positions` — открытые связки и запас до ликвидации.
- Нет писем/сообщений от healthchecks.io — значит, бот всё время был жив.

### Раз в неделю

- Убедитесь, что в Telegram каждый день приходил файл резервной копии `shio-ГГГГ-ММ-ДД.db.enc`
  (в 03:00 UTC). Пара последних файлов пусть хранится у вас.
- Зайдите на сервер и посмотрите, сколько свободно места на диске:

```bash
df -h /
```

OK — в столбце `Use%` меньше 80%.

- Проверьте, не просит ли система перезагрузку после автоматических обновлений:

```bash
ls /var/run/reboot-required
```

Если напечатано `No such file or directory` — перезагрузка не нужна. Если напечатано
`/var/run/reboot-required` — перезагрузите сервер:

```bash
sudo reboot
```

Соединение оборвётся — это нормально. Бот поднимется сам через 3–5 минут (проверьте `/status` в
Telegram); healthchecks.io может прислать короткую тревогу и затем «Shio is UP».

### Обновление бота

Когда разработчик скажет, что вышла новая версия:

```bash
cd ~/shio
```

```bash
./deploy.sh
```

Скачивает новую версию и перезапускает бота (позиции при этом не закрываются: бот дозавершает
текущий шаг и останавливается, после запуска сам сверяет позиции). OK — как в шаге 9.

### Изменить настройки

После любой правки `config.local.yaml` или `.env` бот нужно перезапустить, иначе он не увидит
изменений:

```bash
./deploy.sh restart
```

Перезапускает бота с новыми настройками, ничего не скачивая (остановка занимает до минуты), и ждёт
сигнала «жив». OK — как в шаге 9: `== Движок работает ==` и состояние бота. Если вместо этого
`Движок не запустился` — скорее всего, ошибка в `config.local.yaml`: выполните `./deploy.sh doctor`.

### Журнал (логи)

```bash
./deploy.sh logs
```

Показывает последние 200 строк журнала бота и дальше новые строки в реальном времени. Выход —
Ctrl+C (бот при этом продолжает работать). Тот же журнал лежит в файлах `data/shio.log*`.

### Состояние из терминала

```bash
docker compose ps
```

OK — у `engine` в столбце STATUS `Up … (healthy)`. Если там `(unhealthy)` или не `Up` —
`./deploy.sh restart`.

```bash
docker compose exec engine python -m engine status
```

То же, что `/status` в Telegram, но на сервере.

### Восстановление из резервной копии

Нужно, если база испорчена или вы переносите бота на новый сервер (там сначала пройдите шаги 1–9
с **тем же** ключом `SHIO_BACKUP_KEY` из менеджера паролей).

1. Скачайте из Telegram нужный файл `shio-ГГГГ-ММ-ДД.db.enc` на компьютер. Telegram Desktop на
   Windows сохраняет файлы в папку `Загрузки\Telegram Desktop` (`Downloads\Telegram Desktop`).
2. На **вашем компьютере** откройте новое окно PowerShell/Terminal и перейдите в эту папку.
   На Windows:

```bash
cd "Downloads\Telegram Desktop"
```

На Mac (Telegram сохраняет в «Загрузки» или в `Загрузки/Telegram Desktop` — проверьте в Finder):

```bash
cd Downloads
```

Не нашли файл — не страшно: напечатайте в окне `scp ` (с пробелом), **перетащите файл мышкой в
окно терминала** — появится полный путь к нему — и допишите ` shio@<IP-сервера>:~/`.

```bash
scp shio-ГГГГ-ММ-ДД.db.enc shio@<IP-сервера>:~/
```

Копирует файл на сервер в домашнюю папку (подставьте настоящую дату из имени файла).
OK — строка с именем файла и `100%`.

3. **На сервере:**

```bash
cd ~/shio
```

```bash
./deploy.sh restore ~/shio-ГГГГ-ММ-ДД.db.enc
```

Останавливает бота, расшифровывает копию, подменяет базу и запускает бота снова. Прежняя база не
удаляется: путь к ней будет напечатан (`Прежняя база сохранена: …`). OK — в конце `Готово.`
Если ключ в `.env` не тот или файл повреждён — база не меняется, бот работает со старой.

Если Telegram был недоступен, копии сохраняются на сервере в `data/backups/` (14 последних); их
можно указывать прямо: `./deploy.sh restore data/backups/shio-ГГГГ-ММ-ДД.db.enc`.

## 11. Первые 2 недели: виртуальный режим

Сейчас бот торгует **виртуально**: ордера считаются по настоящим ценам и стаканам бирж, комиссии
вычитаются, funding начисляется по настоящим выплатам, но **денег на биржах нет и они не
тратятся**. API-ключи бирж не нужны. Цель двух недель — проверить, что бот стабилен и что стратегия
зарабатывает после комиссий, прежде чем переходить к этапу 5 (реальные деньги).

Учтите: в режиме `semi` (по умолчанию) связка открывается, только когда вы нажмёте «Открыть» в
предложении. Нажимайте на те, которые взяли бы и за настоящие деньги. Если хотите, чтобы бот сам
набирал статистику без вас, добавьте в `config.local.yaml`:

```yaml
engine:
  mode: auto
```

и перезапустите: `./deploy.sh restart`.

### Что записывать каждый день

Заведите табличку (Google Таблицы или тетрадь) и раз в день переписывайте из ежедневной сводки:

| Дата | Капитал | P&L за день | Funding за день | Открытых связок | Были тревоги? | Сообщения от healthchecks? |
|---|---|---|---|---|---|---|

Для каждой открытой связки запишите из предложения **ожидаемую прибыль** (`~… USD`) и доходность,
а при закрытии — сколько funding она **на самом деле** получила (`/positions`, строка `funding`) и
итог `реализовано`.

### Что считать успехом перед этапом 5

- Бот проработал 14 дней без падений: healthchecks.io не присылал тревог (кроме ваших
  перезапусков), `docker compose ps` всё время показывает `Up … (healthy)`.
- `P&L всего` в `/status` **положительный** — в нём уже учтены комиссии за вход и выход.
- Сделок достаточно, чтобы судить: хотя бы несколько связок открыто и закрыто. Одна удачная
  сделка — ещё не статистика.
- Фактический funding по связкам примерно совпадает с ожидаемым из предложений (не ниже, скажем,
  половины ожидаемого). Если факт стабильно намного хуже — стратегию надо донастроить до реальных
  денег.
- Резервные копии приходили каждый день, и вы хотя бы раз проверили восстановление (раздел 10).

**Честно:** это виртуальные результаты. В реальной торговле будут проскальзывания, задержки,
частичные исполнения и, возможно, другие комиссии (ваш уровень на бирже). Положительный
виртуальный итог — необходимое, но не достаточное условие для перехода к реальным деньгам.

## Что делать, если…

**…пришла тревога от healthchecks.io («Shio is DOWN») или бот молчит в Telegram.**
Зайдите на сервер (`ssh shio@<IP-сервера>`, `cd ~/shio`) и посмотрите журнал:

```bash
./deploy.sh logs
```

Последние строки обычно объясняют причину. Затем:

```bash
docker compose ps
```

Если у `engine` написано `(unhealthy)`, он не `Up` или его нет в списке — перезапустите:

```bash
./deploy.sh restart
```

OK — `== Движок работает ==`. (`./deploy.sh` без слов — только для обновления бота.) Если сервер
не пускает по SSH вовсе — зайдите в панель провайдера: сервер может быть выключен.

Если бот завис (10 минут не завершает ни одной задачи), он перезапускается сам: в журнале будет строка
`Движок завис N с — перезапуск`, а через пару минут бот снова работает. После любого
нештатного перезапуска (сбой, зависание, нехватка памяти) бот пишет в Telegram: «⚠️ Движок
перезапущен после сбоя (последний сигнал «жив» был в ЧЧ:ММ UTC). Позиции проверяются.» — он сам
сверяет позиции, делать ничего не нужно. После обычного `./deploy.sh` или `./deploy.sh restart`
такого сообщения нет. Если такие сообщения приходят часто — сообщите разработчику.

**…сервер перезагрузился** (провайдер, обновление). Ничего делать не нужно: Docker поднимет бота
сам (`restart: always`). Через 3–5 минут проверьте `/status`. Если не поднялся — пункт выше.

**…нужно обновить бота.** `cd ~/shio`, затем `./deploy.sh` (раздел 10).

**…`./deploy.sh` пишет «git pull не удался».** Возможны две причины:
1. Изменены файлы проекта на сервере (например, `config.yaml`). Выполните `git status` — увидите,
   какие. Перенесите свои изменения в `config.local.yaml` и верните файл: `git checkout config.yaml`.
2. Истёк срок токена GitHub (шаг 4.1). Создайте новый токен так же, затем `nano ~/.git-credentials`
   и замените старый токен (часть между `:` и `@` в строке
   `https://vladmosharskiy84-cmyk:ТОКЕН@github.com`) на новый.

**…`Ошибка: движок не сможет писать в data`.** Выполните команду, которую напечатал `deploy.sh`
(`sudo chown -R 1000:1000 …/data`), и повторите.

**…`Ошибка: config.local.yaml — папка, а должен быть файлом`.** Выполните `rm -r config.local.yaml`,
затем `cp config.local.yaml.example config.local.yaml` и заново впишите chat_id (шаг 5.4).

**…нужно восстановить базу.** Раздел 10, «Восстановление из резервной копии».

**…хочется остановить торговлю.** В Telegram: `/pause` — не открывать новые связки (открытые
охраняются), `/resume` — снять паузу, `/stop` — закрыть все связки и поставить на паузу.

**…бот прислал «Резервная копия не сделана: не задан ключ шифрования».** Шаг 6, затем перезапуск:
`./deploy.sh restart`.
